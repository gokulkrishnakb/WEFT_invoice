# Full-Stack Development Task: Sales Invoice Management System

Act as a Senior Full-Stack Software Engineer. Your task is to design and develop a complete, functional, production-quality Sales Invoice Management System based on the requirements below.

This is a technical assessment assigned by a company after an interview. The original assignment specifies .NET Core, Angular, and SQL Server. However, the company has explicitly permitted the following alternative technology stack.

## 2. Project Objective

Develop a Sales Invoice Management System that allows users to:
- Create sales invoices.
- Add multiple products/items to an invoice.
- Automatically calculate item totals and invoice totals.
- View all invoices.
- View individual invoice details.
- Edit existing invoices.
- Delete invoices.
- Generate and filter invoice reports.

The application must have a fully functional frontend connected to the FastAPI backend and PostgreSQL database.

## 3. Database Design

Create the following two primary database tables.

### Table 1: invoices

Fields:

- id: Primary key, auto-increment.
- invoice_number: Unique, automatically generated.
- customer_name: String, required.
- date: Date, required.
- total_amount: Numeric(12,2), calculated automatically.

### Table 2: invoice_items

Fields:

- id: Primary key, auto-increment.
- invoice_id: Foreign key referencing invoices.id.
- product_name: String, required.
- quantity: Numeric(12,2), required.
- price: Numeric(12,2), required.
- total: Numeric(12,2), calculated as quantity × price.

Relationship:
- One invoice can contain multiple invoice items.
- Implement a proper one-to-many relationship using SQLAlchemy.
- Deleting an invoice should also delete its associated invoice items.
- Use appropriate foreign key constraints and cascading behavior.

Use PostgreSQL NUMERIC/DECIMAL for financial calculations instead of floating-point types.

## 4. Invoice Number Generation

Invoice numbers must follow this format:

26INV0001

Format:
- 26 = Last two digits of the current year.
- INV = Fixed identifier.
- 0001 = Sequential invoice number.

Examples:
- 26INV0001
- 26INV0002
- 26INV0003

Requirements:
- Generate invoice numbers automatically on the backend.
- Users must not manually enter invoice numbers.
- Invoice numbers must be unique.
- Ensure concurrent invoice creation cannot generate duplicate invoice numbers.
- Start the sequence from 0001 for each new year.
- Preserve existing invoice numbers when editing invoices.

## 5. Backend API Requirements

Implement versioned REST APIs under:

/api/v1/

### Create Invoice

POST /api/v1/invoices

Accept:
- Customer name.
- Invoice date.
- Multiple invoice items.
- Product name.
- Quantity.
- Price.

Backend responsibilities:
- Validate required fields.
- Calculate each item's total.
- Calculate the invoice's grand total.
- Generate the invoice number.
- Save the invoice and its items in a single database transaction.
- Return the created invoice.

### Get All Invoices

GET /api/v1/invoices

Requirements:
- Return invoices with pagination.
- Support page and limit parameters.
- Support invoice number filtering.
- Support date filtering.
- Return total record count and pagination metadata.

### Get Invoice by ID

GET /api/v1/invoices/{id}

Return:
- Invoice information.
- Invoice number.
- Customer name.
- Date.
- Total amount.
- All associated invoice items.

### Update Invoice

PUT /api/v1/invoices/{id}

Requirements:
- Update customer name.
- Update invoice date.
- Add new invoice items.
- Update existing invoice items.
- Remove deleted invoice items.
- Recalculate item totals.
- Recalculate invoice grand total.
- Do not change the original invoice number.
- Perform updates transactionally.

### Delete Invoice

DELETE /api/v1/invoices/{id}

Requirements:
- Delete the invoice.
- Delete its associated items.
- Return a meaningful success response.
- Handle non-existent invoice IDs appropriately.

## 6. Validation and Error Handling

Implement proper backend validation using Pydantic.

Validation rules:
- Customer name is mandatory.
- Invoice date is mandatory.
- At least one invoice item is required.
- Product name is mandatory.
- Quantity must be greater than zero.
- Price must be non-negative.
- Reject invalid or missing data.
- Prevent negative invoice totals.
- Return appropriate HTTP status codes.

Use meaningful error messages and consistent API response structures.

Handle:
- 400 Bad Request.
- 404 Not Found.
- 422 Validation Error.
- 500 Internal Server Error.

Never expose database credentials or internal exception details to the frontend.

## 9. Backend Architecture

Organize the backend into separate modules.

Suggested structure:

backend/
    app/
        main.py
        database.py
        models/
            __init__.py
            invoice.py
            invoice_item.py
        schemas/
            invoice.py
        routers/
            invoice.py
        services/
            invoice_service.py
        core/
            config.py
    requirements.txt
    .env.example

Responsibilities:

- models: SQLAlchemy database models.
- schemas: Pydantic request and response models.
- routers: API endpoints.
- services: Business logic and calculations.
- database: PostgreSQL connection and session management.
- core: Environment configuration.

Keep API routes thin. Put business logic in the service layer.
